- (event) bmad-architecture run 1: brownfield scan of src/rapoo_vt7, tests, tools/probe.py done; ratifying Phase-1 conventions for Phase 2+ (spec-rapoo-vt7, SPEC.md adopted as input).
- (note) Existing clean seam: protocol.py holds pure wire constants; device.py is the only module doing hidraw I/O (os.open/write/read, select, ioctl), interface scan by report-descriptor rid 6, hot-swap on timeout.
- (note) Existing pattern: BatteryMonitor is a daemon thread owning the fd, push model via callbacks on_update/on_state; GUI consumes via GLib.idle_add bridge; state machine connected/asleep/disconnected/error.
- (note) Existing gap 1: read_response() drops any non-rid6-ACK report while awaiting a command reply — report 7 (DPI/rate/gear/mode) must be routed, not lost, in Phase 2.
- (note) Existing gap 2: fd ownership is exclusive to the monitor thread, reopened per cycle; Phase 2 GUI commands (write_eeprom, DPI, remap) need serialized access — two fds on the same hidraw means busy; GUI thread must never block on device I/O.
- (note) Conventions to ratify: tests via python3 -m unittest discover -s tests with FakeDev/FakeClock/Collector injection into BatteryMonitor; all user strings through i18n.LANGS (pt_BR/en/es); icons via pycairo absolute PNG path; config.json under ~/.config/rapoo-vt7.
- (decision) AD-1 paradigm (user-confirmed): callback/push, single producer, layered — device session mediates all hidraw I/O; GUI consumes pushed state, never owns transport. Prevents any module from touching hidraw or protocol bytes directly.
- (decision) AD-2 report routing (user-confirmed): a single worker loop select()s the fd and routes every report — rid 6-ACK completes the pending command, rid 7 updates state/notify; nothing is dropped while a command is in flight. Prevents lost passive data (DPI/rate) and racing readers.
- (decision) AD-3 fd ownership + serialization (user-confirmed): the worker is the exclusive fd owner; GUI commands are enqueued as requests returning futures; GUI never holds the fd and never blocks on device I/O. Prevents busy-fd conflicts within the app and GTK-main-loop stalls.
- (decision) AD-4 state shape (user-confirmed): device state is one immutable snapshot (battery, status, mode, asleep, DPI gear, dpiX/dpiY, rpt_24g/rpt_usb, config) pushed upward by the worker; consumers render the latest snapshot and never mutate it. Prevents two fields being written by two owners and partial-state renders.
- (decision) AD-5 threading boundary (ratified): GTK main loop is the only UI thread; worker thread is the only device thread; crossing via GLib.idle_add for pushes and future callbacks for command results. Prevents GTK blocking on I/O and UI mutation off the main thread.
- (decision) AD-6 settings registry + golden rule (ratified from CAP-4): settings.py is a pure core module (no GTK import) mapping named fields to (addr, size, type, range, validator); every write goes through it and is verified by immediate re-read; no write path exists before the baseline JSON (dump in 24-byte blocks). Prevents raw addresses leaking into GUI and unverified/unbacked writes.
- (decision) AD-7 GUI-only surface + i18n (ratified from SPEC constraint): all user-manipulable features (CAP-5-8) reachable from the menu/dialogs; every user string via i18n.LANGS (pt_BR/en/es); icons via pycairo absolute PNG path. Prevents unlocalized strings and CLI-only features.
- (decision) AD-8 error model (ratified): typed exceptions from device (DeviceNotFound/DeviceOpenError/CommandTimeout) map to states (connected/asleep/disconnected/error) and non-blocking GUI surfacing (notification/dialog); sleep keeps listen-only discipline, no command spam. Prevents blocking error dialogs and command flood when asleep.
- (decision) AD-9 CLI separation (ratified): tools/probe.py is a separate process with its own fd for diagnostics/validation (--dump/--status); the app process instantiates exactly one fd (the worker's) at a time. Prevents the app opening a second concurrent fd and the worker being reused by the CLI.
- (note) Inherited from SPEC-rapoo-vt7 (binding, read-only): direct hidraw only, VT_nrf54L protocol only (no ClickSync), EEPROM golden rule, mouse-asleep discipline, identification by rid-6 report descriptor + udev both PIDs, stack GTK3+AppIndicator+pycairo, Linux-only single user. Deferred here, owned by the spec.
- (question) Open question for Phase 2+ design: should the DPI gear switch also be available via the physical DPI+ / DPI- buttons (device-side), or only configured via the menu? (product behavior, not architecture)
- (decision) AD-2/AD-3 clause (from adversarial review): command lifecycle — exactly one command in flight (pipeline depth 1), FIFO queue; an ACK with no pending command is dropped and counted, never buffered; futures resolve exactly once (success / CommandTimeout / Cancelled / DeviceGone); a late ACK after timeout never completes a future. Wire has no per-command correlation, so ordering must be total.
- (decision) AD-8 clause (from review): user-command-while-asleep — queued but not sent; queue drains FIFO on wake (first report 7); empty report 06 00 is a sleep signal routed to the state machine (fast path), not ignored; pending user command surfaces non-blocking as pending, move the mouse.
- (decision) AD-6 rewrite (from review): settings.py is a pure registry + codec (no device import, no I/O, no GTK); the worker is the sole golden-rule executor (baseline check, write, re-read) operating on Field metadata; read-modify-write is ONE atomic queue entry; registry stores raw bytes + size/type so Phase-1 format fixes are data edits. Mermaid edge settings-to-device removed; session-to-settings is the direction.
- (decision) AD-4 clause (from review): every snapshot field carries declared source, type, range, raw-not-derived storage, precedence (write-verify re-read supersedes report 7 for that field until a newer report 7 with a different value), retention on asleep/disconnected (keep last known, never null); mode split into connect_mode (report-7 data[1]) and work_mode (0xA2 raw).
- (decision) AD-3 clause (from review): hot swap is owned by the worker; the transport auto-retry (device.query _try_next replay) is retired; a command spanning an interface switch is NOT replayed, it resolves typed with the interface-change reason; writes are single-execution.
- (decision) AD-10 (from review): config.json has one owner with atomic read-modify-write replace (save_language must not clobber other keys); a shared baseline-path constant (~/.cache/rapoo-vt7/eeprom_baseline.json) consumed by both probe.py --dump and the worker golden-rule check; ops envelope ratified — GApplication single instance + --hidden + autostart is the only thing preventing a second fd from another process.
- (decision) AD-7 clause (from review): icons.py is the sole owner of icon-name derivation (icon_name/UNKNOWN_NAME); tray.py must not inline the filename pattern.
- (decision) AD-8 clause (from review): the battery.py-to-session.py migration keeps the sleep FSM verbatim (quiet listen 60s reopen, recheck/fallback/retry timings) with the command queue added; a story cannot drop the quiet-reopen behavior that sleep/wake depends on.
