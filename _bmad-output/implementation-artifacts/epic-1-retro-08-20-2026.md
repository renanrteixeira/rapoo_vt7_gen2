## Findings

Consolidated from two delegated analyses (aggregate views; adversarial + edge-case + verification-gap lenses over the narrowed epic scope) plus the behavior check. Every finding carries its source.

### High

- **F1 (golden rule not in code)** — "No EEPROM field may be written before a baseline backup exists" (spec 1-2 Intent) is enforced nowhere in the app write path: `BatteryMonitor.submit` (`src/rapoo_vt7/battery.py:77`) and every GUI write call site (`dpi.py:122-125,192,216-217`; `performance.py:118,190,218`; `parameters.py:212,240`; `buttons.py:551`; `system.py:271`) write with no baseline check. The only gate is the untested diagnostics tool `tools/writetest_c.py:46-50`. Process discipline held so far (baseline captured 2026-08-10 before any write), but the epic's core safety intent lives only in convention. Disposition: **fix now**.
- **F2 (no-replay invariant untestable by the suite)** — spec 1-1 AC "never re-sent or replayed on another interface" has no regression-catching test: `make_device()` leaves `_candidates = []` (`tests/test_device.py:24-28`), so a regression of `write_eeprom` to `query()` would still pass `mwrite.assert_called_once()` (single-candidate path re-raises after one send, `device.py:239`). The 2-candidate interface-switch double-write scenario is untested. Disposition: **fix now**.
- **F3 (AD-3 contradiction still live)** — the spine declares transport auto-retry "retired" (ARCHITECTURE-SPINE.md:64) but `device.query` still replays across an interface switch on timeout (`device.py:237-242`, `_try_next` at `device.py:146-154`), and the destructive factory reset `0xAD` goes through it (`system.py:210-214`). Bounded (reset ≈ idempotent) but it is the exact replay class story 1-1 was written to prevent. Disposition: **fix now** (route 0xAD through single-execution send/read or record an accepted-deviation note).

### Medium

- **F4 (stale-ACK misattribution)** — `read_response` ignores its `cmd_id` argument (`device.py:201-223`); any rid-6 ACK frame satisfies `write_eeprom`'s wait. A late ACK from a previously timed-out command can return the write early → spurious verify mismatch while the write lands later. Inherent (protocol has no correlation id); undocumented. Disposition: **accept** (document at the primitive).
- **F5 (multi-field writes non-atomic)** — `dpi.set_gears` issues 3 independent single-execution writes (X list, Y list, enable; `dpi.py:122-125`); a timeout mid-sequence pairs new X with stale Y/count on the physical button cycle. Correctly no auto-retry; no caller compensates. Disposition: **defer**.
- **F6 (string codec divergence)** — `settings.Field.encode` silently truncates UTF-8 and can emit fewer than `size` bytes unpadded (`settings.py:37-43`), while `system.encode_name` rejects >16 B/embedded NUL and pads correctly (`system.py:237-247`). Latent trap: currently unreachable (`system.py` bypasses the registry codec); ASCII-only tests (`tests/test_settings.py:148-160`). Disposition: **fix now** (align policy + multibyte test).
- **F7 (registry drift)** — `sensor_mode` registered as 1 byte (`settings.py:86`) vs validated 7-slot table (`performance.py:64-67`, `system.py:148`); §C params registered twice under different names (`settings.py:99-107` vs `parameters.py:30-42`); button offsets duplicated in `buttons.BUTTONS` (`buttons.py:26-40`); `Field.validator` hook is dead code (`settings.py:27,56-59`, zero users/tests). Spec 1-3 required format corrections fed back into FIELDS as data edits — the post-story discoveries never were. Disposition: **fix now** (reconciliation pass).
- **F8 (EEPROM slice helper duplicated ~11×)** — `read_eeprom` returns raw reply; the `resp[EEPROM_DATA_OFFSET:+n]` slice + error strings are re-implemented at 11 sites across 7 files, including a byte-for-byte copy-pasted `_read()` in 4 modules (`performance.py:70-76`, `parameters.py:140-146`, `buttons.py:403-409`, `system.py:130-136`). Disposition: **fix now** (one shared helper).

### Low / accepted observations

- `dump_main` conflates device-read and file-write `OSError` (`probe.py:885-902`) — misleading message only.
- Address bytes masked not validated (`device.py:262,276-277`) vs bounds-guarded `eeprom_bank0` (`protocol.py:184-190`).
- Shared-byte RMW race window across processes (`performance.py:116-118`); requires concurrent writers.
- Read-side guards untested: `length > 24` (`device.py:259-260`), `length == 0` unguarded; `eeprom_bank0` out-of-bank raise untested (`tests/test_settings.py:96-103` covers in-bank only).
- Wake-hint message content unasserted (`tests/test_probe.py:411-420` asserts rc only).
- `--status` cross-validation TOCTOU (report 7 captured before DPI reads, `probe.py:193-194` then `313`) — inherent, no ordering note emitted.
- `probe.py` god-tool growth: 1073 lines, 6 argparse modes, 4 stacked concerns, reaches into private `dev._read_report` (`probe.py:1063`) — acceptable for a diagnostics harness per AD-9, watch it.
- Pattern divergence: epic primitives raise English `ValueError`s (`device.py:260-293`, `settings.py:36-58`) while later modules introduced localized ValueError subclasses (`system.py:81-123`, `buttons.py:493-500`); GUI maps via isinstance chains with raw-str fallback (`main.py:495-500,548-550,621-625`).
- Spine deltas (record as accepted deviations): `session.py`/`state.py` never materialized (worker role in `battery.BatteryMonitor`, callback kwargs instead of AD-4 snapshots); feature modules bypass `settings.FIELDS` (only `dpi.py` consumes it); pairing_session opens a second fd (documented deliberate, CONTEXT.md F3); `config.save_language` non-atomic overwrite (`config.py:24-30`) violates the AD-10 pattern `probe.write_baseline` implements correctly (`probe.py:106-126`).
- Superseded criterion (drift record): spec 1-3's "2B button fields print both interpretations" was replaced by 4-byte method decoding (`probe.py:211-222`) — later validated on device (story 4-1).
