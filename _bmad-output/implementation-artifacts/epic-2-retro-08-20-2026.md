## Findings

Consolidated from one delegated analysis (aggregate views + adversarial/edge-case/verification-gap lenses over the narrowed scope) plus the behavior check. Every finding carries its source.

### High

- **F1 (unvalidated device-provided gear byte)** — `read_dpi` returns `gear` raw from EEPROM (`dpi.py:63`); nothing clamps it. IndexError crash paths when `dpi_current > 6` (external writer, A Hub, corruption): `add_gear` (`dpi.py:145`), `set_value` (`dpi.py:224`), and the GTK status render (`gui.py:1486-1489`). `active_count` clamps `enable` (`dpi.py:76-77`) but `gear` has no equivalent. Disposition: **fix now**.
- **F2 (edit/deleted-slot race)** — a spin edit arms a 600 ms timer (`gui.py:1561-1565`); a ✕ delete submitted before it fires compacts the list; the timer then submits `set_value` built from the stale window snapshot (`gui.py:1576-1586` → `main.py:239-251`) — validated only against the stale list (`dpi.py:209-211`) and written at the compacted slot address (`dpi.py:216-217`), overwriting the **surviving** gear. No generation/staleness token exists in the chain. Disposition: **fix now**.
- **F3 (zero render coverage for the DPI tab)** — `tests/test_gui_units.py` headlessly tests params/perf/rate/RF/buttons/pairing render decisions but has **no DPI test**: the DPI render is inline GTK code (`gui.py:1473-1551`), never extracted into a pure plan function. AC1's rendered status (gear/value/cycle count) is asserted nowhere. Disposition: **fix now**.

### Medium

- **F4 (spec AC3 wording inverted)** — AC3 says "preserves the current DPI if the edited gear is current" (spec-2-1:59); the as-built does the opposite by design: editing the *current* gear **applies** live (`dpi.py:212-224`), editing a non-current gear stores (`dpi_stored`). Code matches the documented semantic (CONTEXT.md B2, FEATURES.md:196-199) — the spec sentence is the defect. Disposition: **fix now** (spec reconciliation).
- **F5 (partial-failure / hot-swap states)** — `set_gears` = 3 sequential verified writes (X, Y, enable; `dpi.py:122-125`); failure at Y/enable leaves mixed new-X/old-Y on the physical cycle, no rollback. A hot-swap between write and verify raises `CommandTimeout` after the data landed (`device.py:286-294`) — UI error contradicting device state. Same root as epic-1's deferred F5. Disposition: **defer** (fold into the epic-1 item).
- **F6 (no in-flight guard on DPI actions)** — Add/✕/radio/spin have no busy flag (contrast System tab's cross-disable): double-click queues duplicate tasks both computed from the same click-time snapshot (`main.py:216,229`), re-writing the same target list and possibly moving the current gear from stale `cur` (`dpi.py:148,183`). Disposition: **fix now**.
- **F7 (test gaps)** — no partial-failure fake in `tests/test_dpi.py` (FakeDev always succeeds, `test_dpi.py:41-45`; contrast `test_performance.py:59-73`); untested branches: `_sorted_active` fallback (`dpi.py:98`), delete clamp boundary (`dpi.py:182`), out-of-range device `cur` paths. Assertion strength is adequate (exact address tuples + literal enable bytes would catch offset/count bugs). Disposition: **fix now** (with F1).

### Low / accepted observations

- Report-echo marker assigned after task return → possible duplicate notification or wrongly suppressed later change (`main.py:145-151` vs `257,271,289-297`).
- `wake=True` cost stacking while asleep: up to 4 sequential 1 s-timeout ops per action; repeated clicks queue multiple wake tasks (`battery.py:139-159,205-221`).
- Stale timer after error/lang re-render: `set_dpi_error`/`_on_lang_changed` rebuild without `_cancel_dpi_timers` (`gui.py:1449-1451,1742` vs `1459-1461`) → redundant write + spurious notification.
- Report 7 inside the debounce window silently discards the typed-but-uncommitted edit (`gui.py:1459-1461`).
- Duplicate DPI values allowed; two identical rows visually ambiguous; X/Y pair-keeping under duplicates untested (`dpi.py:95,155`, `gui.py:1514`).
- X-only UI editing: diverged Y survives until add/delete force y=x (`gui.py:1524-1533`, `main.py:247`, `dpi.py:143-144,173`) — asymmetry undocumented.
- Pattern divergence vs later modules: dpi.py never re-inspects verify readback content (perf/params do, `performance.py:118-120`; `parameters.py:212-214`); `read_dpi` all-or-nothing vs per-field isolation in parameters/buttons; range in `settings.Field` but step-grid only in `dpi._validate_dpi`; DPI errors are the only config-tab errors never localized (`main.py:810-811`).
- Duplication: short-reply read helper ×3 modules (epic-1 F8 covers); FakeDev copy-pasted across ≥4 test files; last-gear/full-cycle rules enforced at both layers (defense in depth — acceptable).
- Startup eagerly loads DPI (~16 EEPROM reads) regardless of tab visibility (`main.py:167-169`) — adjacent to the P7 power concern.
- Undocumented scope growth: `set_gears`/`add_gear`/`delete_gear`/`_sorted_active` absent from the spec's approach/code map (documented in FEATURES.md:180-222 instead).

### Checked and clean

`active_count` clamping incl. 0xFF→7 (tested); last-gear refusal at both layers (tested); Add disabled at 7 slots (GUI+API, tested); delete re-select matches A Hub semantics incl. shift/keep cases (tested); sorted-add keeps current gear by VALUE across reorder (tested incl. reorder); spin debounce coalesces; rebuild cancels timers on the update path; `_dpi_loading` guard suppresses synthetic signals during rebuilds; every write via `write_eeprom_verify`; no non-DPI field touched; no rate/perf controls in the tab; all user actions `submit(wake=True)`; report-7 mirror with echo suppression present; mock tightness adequate for offset/count regressions.
