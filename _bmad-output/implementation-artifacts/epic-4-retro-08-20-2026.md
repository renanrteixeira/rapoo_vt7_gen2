## Findings

Consolidated from one delegated analysis (spec-drift + deferred-item verification + aggregate views + three lenses) plus the behavior check. Sources are file:line in the current tree.

### Spec drift (dominant finding)

- **F1 (2026-08-19 wave vs frozen spec)** — commit `2357353` moved keyboard (104 keys), combos (10 presets) and macros (12 slots) INTO the picker (`buttons.py:103-373`, dialog `gui.py:1090-1211`), validated on device (kb_a/edit_copy/macro_5 reversible writes on 0x0634, FEATURES.md §2.D). But the frozen spec still says these categories are `_DECODE_ONLY` "**never offered/written**" (`spec-4-1:255-257`, patch entry `:193-195`) and its change log ends 2026-08-12 at suite 273. The Ask First gate itself was honored (formats matched the bundle → no HALT condition; device validation done before offering), yet three layers of text were never reconciled: the frozen boundary prose, the change log, and **stale in-code comments** contradicting shipped behavior (`buttons.py:46-51`, `:15-19`, `:92-95`; `gui.py:702-704`). Disposition: **fix now** (doc/comment-only batch).
- **F2 (legacy dead path)** — `_button_combos` written at `gui.py:398,1044,1074`, never read; `_on_button_changed` ComboBoxText handler kept explicitly "for the pre-dialog picker tests" (`gui.py:1213-1230`, tests `test_buttons.py:607-635`). Disposition: **decide** (remove or document as test fixture).

### Verification gaps

- **F3 (wave test debt)** — zero coverage of the picker dialog itself (`_on_button_pick`/`_picker_*`, grep over tests/: none); `set_function` never exercised with a keyboard/combo/macro id (all 6 test calls use METHODS fns — the wave's write path is covered only by manual device validation); probe decode of new categories integration-untested (`test_probe.py:227-250` covers unknown + mouse_left only); i18n placeholder parity omits `picker_title {button}` / `fn_macro {n}` (`test_i18n.py:71-103`). Disposition: **fix now**.
- **F4 (`_other_is_left` fails closed)** — returns `False` on any read failure (`buttons.py:483-490`), so a flaky BLE field read makes the rule **refuse** a legitimate left remap — safe direction, but the docstring ("a flaky field must not block the ≥1-left rule", `:485-486`) describes the opposite of the actual effect. Disposition: **fix now** (docstring/semantics alignment).
